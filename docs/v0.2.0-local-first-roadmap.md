# Map Daddy v0.2.0 Local First Roadmap

## Release Goal

Map Daddy v0.2.0 should make the first browser-only projection mapping experience work in under five minutes without requiring a backend, relay, account, Raspberry Pi, or cloud setup.

Target workflow:

1. Open Map Daddy in a browser.
2. Create a project.
3. Upload image media.
4. Add or select a surface.
5. Drag surface corners onto a flat wall, poster, screen, or panel.
6. Open the projector route in another tab or window.
7. Fullscreen the projector output.
8. Refresh and keep the project and image media intact.

## Product Decisions

- Audience: people who do not want to pay for projection mapping software and want an easy way to use the technology.
- First target users: hobbyists, makers, students, small creative teams, and people who need simple projection mapping without production-suite complexity.
- First success path: browser-only.
- First mapping target: flat wall/poster; angled wall/corner is next.
- First output target: one projector.
- First precision tools: mouse dragging, keyboard nudging, and calibration grid later.
- First storage model: local-first browser storage.
- First sync model: same-browser editor/projector sync without relay.
- Backend and relay: optional enhancements, not required for the first success path.

## In Scope

### 1. IndexedDB Image Persistence

Images uploaded in local/browser mode must persist after refresh.

Requirements:

- Store uploaded image files as IndexedDB blobs.
- Keep project metadata in the existing project repository abstraction.
- Save media records with stable local media IDs.
- Resolve local media records into object URLs when rendering/editor preview needs them.
- Revoke stale object URLs when no longer needed.
- Preserve current backend upload behavior as an optional hosted path when configured.
- Warn users that videos are session-only until durable video storage is implemented.

Suggested files:

- `frontend/src/lib/projects/projectRepository.ts`
- `frontend/src/lib/projects/types.ts`
- New file: `frontend/src/lib/projects/localMediaStore.ts`
- Potentially `frontend/src/components/editor/MediaPanel.tsx`

Acceptance criteria:

- Uploading an image while backend is unavailable stores it in IndexedDB.
- Refreshing the editor reloads the project and image.
- Opening the projector tab after refresh renders the persisted image.
- Deleting a project should remove orphaned local media where practical.
- Existing backend media URLs still work.

### 2. Same-Browser Projector Sync Without Relay

Editor and projector tabs in the same browser should sync project changes without the WebSocket relay.

Requirements:

- Use `BroadcastChannel` when available.
- Fall back to `storage` events if `BroadcastChannel` is not available.
- Keep the existing relay client as an enhancement when configured and connected.
- Never block editing when no projector is connected.
- Show quiet status text such as `Local` or `Synced` instead of exposing implementation details.

Suggested files:

- `frontend/src/lib/realtime/realtimeClient.ts`
- New file: `frontend/src/lib/realtime/localProjectChannel.ts`
- `frontend/src/app/editor/[projectId]/page.tsx`
- `frontend/src/app/projector/[projectId]/page.tsx`
- `frontend/src/components/editor/ProjectorStatus.tsx`

Acceptance criteria:

- Opening `/projector/:projectId` in another tab shows the latest locally saved project.
- Moving a surface in the editor updates the same-browser projector tab without relay running.
- Relay still works when configured.
- Editor remains usable when no projector is connected.

### 3. Empty-State First-Run Checklist

The editor should be obvious without a modal tour.

Requirements:

- Show a small checklist only when the project has no useful content.
- Checklist should disappear or de-emphasize once media and at least one surface exist.
- Avoid blocking the editor.
- Avoid long instructional text.

Checklist items:

- Upload media.
- Add or select a surface.
- Drag corners.
- Open projector.
- Fullscreen projector.

Suggested files:

- New file: `frontend/src/components/editor/FirstRunChecklist.tsx`
- `frontend/src/app/editor/[projectId]/page.tsx`

Acceptance criteria:

- New blank projects show the checklist.
- Projects with media and surfaces do not show the checklist.
- Checklist does not overlap or block core controls on desktop or mobile.

### 4. One-Click Sample Media

Users should be able to get something mapped even if they do not have media ready.

Requirements:

- Add an `Add Sample` action near media upload or the first-run checklist.
- Use a small local generated image or static asset.
- Store the sample through the same local media persistence path as uploaded images.
- Create or size a surface for the sample if no surface exists.

Suggested files:

- `frontend/src/components/editor/MediaPanel.tsx`
- `frontend/src/app/editor/[projectId]/page.tsx`
- Optional asset under `frontend/public/` or generated canvas-to-blob helper.

Acceptance criteria:

- Clicking `Add Sample` creates visible media and a surface.
- The sample survives refresh.
- The sample appears in the projector tab.

### 5. Quiet Projector Connection Warning

The editor should show connection state without blocking work.

Requirements:

- Show a quiet `No projector connected`, `Local projector connected`, or `Synced` status.
- Do not block save, edit, upload, or projector-link actions.
- Keep status compact in the existing editor header.

Suggested files:

- `frontend/src/components/editor/ProjectorStatus.tsx`
- `frontend/src/app/editor/[projectId]/page.tsx`

Acceptance criteria:

- New projects can be edited with no projector open.
- Opening a same-browser projector tab updates status where feasible.
- Relay connection status remains understandable when hosted sync is configured.

## Out Of Scope For v0.2.0

- Raspberry Pi setup.
- Multi-projector support.
- Accounts or cloud project ownership.
- Masks.
- Edge blending.
- Timelines.
- Advanced durable video storage.
- Object/prop mapping workflows.
- Hosted deployment redesign.

## Versioning

When v0.2.0 is ready to ship:

- Update root `VERSION` to `0.2.0`.
- Update `frontend/package.json` and `frontend/package-lock.json` to `0.2.0`.
- Update visible version labels through `frontend/src/lib/version.ts`.
- Update `README.md` current public version.
- Tag the release as `v0.2.0` after merge.

## Testing Plan

### Frontend Build

Run:

```powershell
cd frontend
npm run build
```

Expected result:

- Vite build succeeds.

### Playwright E2E Tests

Add tests to `frontend/tests/app.spec.ts`.

Required tests:

1. Local image upload persists after editor refresh.
2. Local image project renders in projector route after refresh.
3. Same-browser editor/projector sync works without relay.
4. First-run checklist appears for blank project.
5. First-run checklist disappears or de-emphasizes after media and surface exist.
6. `Add Sample` creates media and a visible surface.
7. Project editing remains possible with no projector connected.
8. Video upload shows a session-only warning in local mode.

Run:

```powershell
cd frontend
npx playwright test
```

Expected result:

- All Playwright tests pass.

### Manual Smoke Test

Run only the frontend if possible:

```powershell
cd frontend
npm run dev
```

Manual path:

1. Open `/dashboard`.
2. Create a project.
3. Upload an image.
4. Confirm the image appears in the media list.
5. Add/select a surface.
6. Drag at least one corner.
7. Open `/projector/:projectId` in another tab.
8. Confirm projector renders the image.
9. Move the surface in editor.
10. Confirm projector updates without relay running.
11. Refresh both tabs.
12. Confirm project and image still load.

## Release Definition Of Done

v0.2.0 is done when:

- A new user can create a project, add image media, map a surface, open a projector tab, fullscreen it, and refresh without losing the image.
- Same-browser projector sync works without relay.
- The editor clearly guides blank projects without modal onboarding.
- Videos clearly communicate session-only behavior in local mode.
- Build and Playwright tests pass.
- Public version is updated to `v0.2.0`.
